本文对应当前浏览器比赛版本。统一加载入口为 `src/physics/runtime.js`，模型目录为 `public/assets/policies/`。动作网络负责关节目标；比赛规则和队伍战术负责何时调用网络。

## 推理输入与执行

共同约束为 **61 维观察量、14 维关节动作、50 Hz 策略、200 Hz 物理**。观察量包括身体角速度、投影重力、相对默认姿态的关节角、关节速度、上一次动作及任务命令。网络输出加到默认姿态上形成关节目标，再由 XL330 / BAM M6 执行器模型转换为驱动力。

| 场景 | 任务命令与附加约束 |
| --- | --- |
| 行走 / 轮滑 | 目标前进、侧向与转向速度；游戏侧向速度通常为 0 |
| 感知球位踢球 | 观察量 55–60 为机器人水平坐标系中的球位置 XY、球速度 XY、冻结射门方向 XY |
| 舞蹈 | 观察量 55–60 为双拍正弦 / 余弦、BPM/120 和舞种编号的三个二进制位 |

足球和舞蹈保留训练契约的 **4 个物理步执行器延迟、1 个控制步关节速度延迟**。足球额外采用 1.75 A 电流限制。观察量归一化已烘焙进这两个 ONNX 导出文件，不需在网页额外重复归一化。

普通行走指令范围为前后 ±0.3 m/s、转向 ±1.5 rad/s；轮滑为前进 0.6 m/s、后退 0.5 m/s、转向 ±0.3 rad/s。冲撞会将行走前进指令提高至最高 0.8 m/s。以上是控制目标，实际速度取决于策略、摩擦、姿态和碰撞。

浏览器使用 ONNX Runtime Web 的单线程 WASM，在 Worker 中执行；本机评估通过 `world.mjs` 使用 ONNX Runtime Node CPU。两者共享 `world-core.js`、机器人碰撞模型和伺服实现。

## 动作切换

1. **普通比赛：** 行走或轮滑网络跟随玩家 / AI 的速度指令。等待时使用零速度指令保持姿态。
2. **射门：** 仅行走模式且未在起身、冲撞或上一射门恢复时接受请求。当前新足球模型执行 1.2 秒；结束后切起身 / 站立网络衔接 1 秒，再回到行走。手动 F 使用触发时的小鸭朝向，AI 瞄准对方球门，射门方向在该次动作期间固定。
3. **跌倒：** 物理姿态持续满足跌倒条件约 0.28 秒后，先稳定约 0.22 秒，再切 `stand`。足够直立后回到移动策略。恢复阶段超时 7 秒或状态无效时，运行时归位该机器人，作为容错。
4. **跳舞：** 先使用真实行走列队，站稳后切训练舞蹈模型及匹配碰撞模型。控制器以 128 BPM 提供舞种和拍点，不直接写关节舞姿。X 在当前实际位姿退出；Space 退出并全场归位。
5. **进球 / 手动归位：** 全部小鸭与足球归位，清空速度、射门、起身、冲撞及 AI 决策状态。进球后进入 3 秒准备；普通 Space 保留本局时间与得分。
6. **终场 / 准备：** 终场冻结物理与计分；开球准备禁止移动、射门与冲撞，由零速度动作保持站立。舞蹈和后台暂停也不消耗有效比赛时间。

## 团队 AI 与冲撞的职责

`src/football-ai.js` 负责同队主攻 / 接应选择、绕到球后、对准球门、避让和卡住后的脱离。角色有保持条件，避免队友反复交换追球职责。它输出速度和射门意图，并不直接移动机器人或足球。

`src/charge.js` 负责冲撞时机：AI 选择站立且距球小于 0.65 m 的对手，双方距离大于 0.22 m、小于 0.55 m，朝向误差小于 0.4 rad。每 5 秒循环检查各自错开的 350 ms 窗口，受 9 秒冷却约束。手动 R 不要求锁定目标，沿当前朝向冲刺。

冲刺最长 1.1 秒，复用行走网络。额外撞击由 `src/physics/charge-impact.js` 处理：真实对手接触、正面接近且相对接近速度至少约 0.12 m/s 后，一次施加上限 0.5 N·s 的冲量，分布于 60 ms，双方反向作用。普通队友碰撞仍由 MuJoCo 处理，不触发对手撞击加成。

因此，**当前有独立足球踢球网络和独立舞蹈网络；团队战术和冲撞尚未独立训练成神经网络**。冲撞可能失败，也可能让双方同时倒地。专项评估数据不构成所有局面都能撞倒的保证。

## 替换与验证

1. 将候选训练源、训练配置、检查点和评估放在训练服务器的独立实验目录；保留固定版本与来源记录。
2. 导出 ONNX，确认 61D / 14D、关节顺序、默认姿态、命令含义、归一化、50/200 Hz 及延迟契约。相同维度并不代表命令语义兼容。
3. 同时更新权重和相应 JSON 的 ID、SHA-256、训练状态、检查点、契约及实际评估结果；碰撞模型变动也要同步 MJCF / 网格。
4. 运行 `npm test` 与 `BASE_PATH=/sim-duck/ npm run build`，并进行浏览器真实比赛、跌倒恢复、射门后恢复、舞蹈原地退出和全场归位验证。
5. 足球候选可用 `FOOTBALL_CANDIDATE=/absolute/path/model.onnx node scripts/evaluate-football.mjs /tmp/candidate.json all` 在本机离线评估。该环境变量只影响评估工具，不会改变已发布网页模型。
6. 将验证后的变更推送 `github-pages`，等待 Actions 测试与部署成功，再检查公开网页。训练完成本身不等于网页已经替换。

评估应同时关注进球、拥挤、倒地、恢复、边角球、动作连续性和浏览器表现。当前已知团队协作与复杂角落仍有改进空间；历史较大球门的指标应与当前规则区别读取。
